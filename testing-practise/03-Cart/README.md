# 03 · Cart — деньги, скидки, доставка

Корзина интернет-магазина: сумма, скидка в процентах, доставка
по порогу, округление до копеек, итог и самый дешёвый товар.

```
dotnet test                 # запустить все тесты этого проекта
dotnet test --list-tests    # только имена, ничего не запускается
```

Сейчас в проекте два зелёных теста-примера — запустите и убедитесь,
что сборка работает. Общая инструкция и справка по xUnit — в `README.md`
в корне архива.

## Где что лежит

```
03-Cart/
  Cart.sln
  src/Cart/Cart.cs            <- код с багами, здесь же спецификация
  tests/Cart.Tests/CartTests.cs   <- ваши тесты, здесь же примеры
```

## Что покрыть тестами

| Метод | Что должен делать |
|---|---|
| `Subtotal` | сумма цен на количество |
| `ApplyDiscount` | вычесть скидку в процентах |
| `Shipping` | 0 от порога, иначе 300 |
| `Round2` | округлить до копеек, половину — вверх |
| `Total` | сумма, скидка, доставка, округление |
| `Cheapest` | самый дешёвый товар |
| `TotalQuantity` | сколько всего штук |

Часть этих методов работает неправильно. Сколько именно — не скажу.

## Спецификация — в комментариях

Над каждым методом в `src/Cart/Cart.cs` написано, что он **обязан**
делать, с примерами. Пишите тесты **по этому описанию**, а не по тому,
что код делает сейчас. Иначе тест просто закрепит баг.

## На что смотреть в первую очередь

- **Опять целочисленное деление, но спрятанное.** `percent` это `int`.
  Посчитайте в уме, чему равно `10 / 100` в C#, и что из этого выйдет.
- **Сумма ровно на пороге бесплатной доставки.** Не 2500 и не 1999,
  а ровно 2000. Спецификация говорит «от 2000 включительно».
- **Скидка 0 и скидка 100.** И скидка за пределами 0..100 —
  спецификация обещает исключение.
- **Округление, когда третий знак — ровно пятёрка.** Возьмите `2.345m`.
  `Math.Round` по умолчанию округляет не так, как учили в школе.
- **Пустая корзина** для поиска самого дешёвого товара.
- **`Total` собран из других методов.** Если он упал, посмотрите,
  не упал ли заодно кто-то из тех, кого он вызывает:
  два красных теста могут означать один баг.
- Деньги — это `decimal`. В тестах пишите суммы с буквой `m`:
  `1000m`, `2.345m`. Иначе не скомпилируется.

## Как записать найденное

```
03-Cart / Shipping
  вход:        sum = 2000
  ожидалось:   0 (от 2000 доставка бесплатная)
  получилось:  300
  тест:        Shipping_ExactlyAtThreshold_IsFree
```

## Что сделано

Шесть сценариев пройдены с использованием отладчика. По каждому
записано: что видно в отладчике, почему так, как починено и как
проверено. После починки каждый сценарий завершается без ошибок и
печатает ожидаемый результат.

Запуск:

    dotnet run --project src/DebugPractise
    dotnet run --project src/DebugPractise -- 1

## Сценарий 1 · Турнирная таблица

**Что увидел.** Точка останова на `Player p = players[i];`. В Locals
одновременно видно `p.Score = 10` и `players[i].Score = 0`. Локальная
копия изменилась, элемент списка — нет.

**Почему.** `Player` — структура (значимый тип). `Player p = players[i]`
копирует значение, а не даёт ссылку. Дальше `p.Score += 10` меняет
локальную переменную, до списка изменение не доходит.

**Починка.** Заменил `List<Player>` на `Player[]`. У массива индексатор
возвращает ссылку на ячейку, поэтому `players[i].Score += 10` пишет
прямо в массив.

**Чем проверил.** С массивом вывод: `Аня 10, Боря 10, Вера 10`.

## Сценарий 2 · Копия команды

**Что увидел.** Точка останова на `Team copy = original;`. После
`copy.Name = "Бета"` поле `original.Name` осталось `"Альфа"`, а после
`copy.Members.Add("Боря")` в `original.Members` тоже появился Боря,
`Count = 2`. В Watch `ReferenceEquals(original.Members, copy.Members)`
вернул `true`.

**Почему.** `Team` — структура, при присваивании её поля копируются
по значению. Но `Members` — это `List<string>`, ссылочный тип.
Копируется не список, а ссылка на тот же объект в куче. Оба поля
смотрят на один и тот же список.

**Починка.** В строке копирования явно клонирую список:
`copy.Members = new List<string>(original.Members);`.

**Чем проверил.** Теперь `original.Members` содержит только Аню,
`copy.Members` — Аню и Борю. В Watch `ReferenceEquals` даёт `false`.

## Сценарий 3 · Карта города

**Что увидел.** В Locals раскрыл словарь: ключи `(1,2)` и `(5,7)` на
месте. `looking = (1,2)` — поля идентичны ключу `(1,2)`. Но
`map.TryGetValue(looking)` вернул `false`. В Watch:
`looking.Equals(map.Keys.First())` → `false`,
`looking.GetHashCode() == map.Keys.First().GetHashCode()` → `false`.

**Почему.** `Point` объявлен как `class`. У класса по умолчанию
`Equals` и `GetHashCode` работают по ссылке. Ключ в словаре и
`looking` — два разных объекта, у каждого свой хэш, `Equals` даёт
`false`. Словарь честно отвечает «нет такого ключа».

**Починка.** Заменил `class Point` на `struct Point`. У структуры
равенство и хэш считаются по полям, поэтому ключ находится.

**Чем проверил.** С `struct` вывод: `найдено = True, name = дом`.

## Сценарий 4 · Игровое поле

**Что увидел.** Точка останова сразу после `var board = new Cell[9];`.
В Locals раскрыл `board` — девять элементов, все `null`. Программа
падает на первой же итерации цикла с `NullReferenceException`.

**Почему.** `Cell` объявлен как `class`, то есть ссылочный тип.
`new Cell[9]` создаёт массив из девяти ссылок, все — `null`.
Объекты `Cell` никто не создал — только место под ссылки.

**Починка.** Заменил `class Cell` на `struct Cell`. Теперь массив
из девяти клеток сразу содержит значения, каждое поле `Value = 0`.

**Чем проверил.** Со `struct` массив заполняется без падений, вывод:
`Готово: 1 2 3 4 5 6 7 8 9`.

## Сценарий 5 · Чистка показаний

**Что увидел.** Точка останова на `foreach`. Список сначала
`[1, -2, 3, -4, 5]`. На второй итерации `value = -2`, вызывается
`readings.Remove(-2)`, список становится `[1, 3, -4, 5]`. На
следующей итерации — исключение `InvalidOperationException:
Collection was modified; enumeration operation may not execute`.
Падение произошло не на строке `Remove`, а на следующем `MoveNext`.

**Почему.** `foreach` использует enumerator, который следит за
версией коллекции. Удаление в теле цикла меняет версию, enumerator
инвалидируется и падает при следующем шаге.

**Починка.** Перебор с конца через обычный `for`:
`for (int i = readings.Count - 1; i >= 0; i--) if (readings[i] < 0) readings.RemoveAt(i);`

**Чем проверил.** Цикл проходит целиком, вывод: `Стало: 1, 3, 5`.

## Сценарий 6 · Длина имён

**Что увидел.** Обычная точка останова на `total += name.Length`
сработала бы 500 раз. Поставил условную с `name == null` — программа
остановилась ровно на `index = 387`. В Locals `name` = `null`.
Без условия упало бы с `NullReferenceException`.

**Почему.** В `LoadNames` после генерации 500 нормальных имён
специально записывается `names[387] = null`. Обращение `name.Length`
к `null` бросает `NullReferenceException`.

**Починка.** В цикле заменил `total += name.Length` на
`total += name?.Length ?? 0;` — null безопасно пропускается как 0.

**Чем проверил.** Программа доходит до конца, печатает суммарную
длину.

## Инструменты отладчика, которые пригодились

- **Locals** с раскрытием вложенных полей — основной инструмент.
  Все баги в этом наборе видны именно там.
- **Watch** с выражениями вроде `ReferenceEquals(a, b)` —
  отвечает на вопрос «это один объект или два».
- **Условная точка останова** (`name == null`) — единственный способ
  не листать 500 итераций.
- **Call Stack** — пригодился в сценарии 5: видно, что падение
  произошло в `MoveNext`, а испортила всё предыдущая строка.
